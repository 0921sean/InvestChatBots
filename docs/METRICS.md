# 지표 측정 & 개선 루프 (Metrics)

> "판단을 생산만 하지 않고 **채점 가능하게**" — 이 시스템이 실매매를 맡을 수 있는지는
> 오직 데이터로만 증명된다. 이 문서는 *무엇을·어떻게 측정하고, 그 지표로 무엇을 개선하는가*를 정의한다.

측정의 원천은 4개 테이블이다: `decision_log`(판단), `weekly_report`(채점 산출), `fetch_health`(데이터 건전성), `benchmark_daily`/`fund_nav`(수익률). 봇 판단은 전부 자동 기록되고(자동 계측), 채점은 결정론적 계산(LLM 0)으로 매주 산출된다.

---

## 1. 무엇을 측정하나 (원천 계측)

### 1-1. 판단 원장 — `decision_log` (모든 봇 판단 자동 기록)
매 판단이 다음과 함께 저장된다. **핵심은 재현성** — "왜 그때 그렇게 판단했나"를 사후 재구성할 수 있어야 감사·개선이 가능하다.

| 필드 | 의미 | 왜 |
|---|---|---|
| `date·bot·code·verdict` | 누가·언제·무엇을·어떻게 판단 | 채점의 기본 키 |
| `reasoning` | 판단 근거 원문 | 정성 분석 |
| `packet` | **판단 시점의 입력 데이터** | 같은 입력 재현·오판 원인 추적 |
| `persona_hash` | 페르소나 프롬프트 버전 해시 | "어느 버전이 판단했나" — 프롬프트 A/B 추적 |
| `source` | 분석/관찰/딥스터디/Q타이밍/Q지수 | 파이프라인 단계별 분해 |

계측 지점: `analyze_stock`(발굴/대형주 분석)·관찰 재점검·딥스터디·Q 타이밍·Q지수 — **전 판단 경로**. 실패해도 매매 로직에 예외를 전파하지 않는다(계측이 거래를 막지 않음).

### 1-2. 데이터 건전성 — `fetch_health`
시세 fetch마다 성공/실패를 일자·소스별로 카운트. LLM 판단의 **입력 품질**을 재는 지표.
- 측정: `record_fetch("price", ok)` — 성공/실패 누적
- 파생: 일일 실패율 = `fail / (ok+fail)`

### 1-3. 수익률 — `benchmark_daily` · `fund_nav`
- `fund_nav`: 계좌별 일일 NAV(현금+투자원가) 스냅샷 → 수익률 곡선
- `benchmark_daily`: 같은 baseline 대비 SPY·QQQ·코스피 누적% → **초과수익(알파) 계측 기준**

## 2. 어떻게 채점하나 (파생 지표 · 공식)

매주 토 09:00 `run_weekly_report()`가 **결정론적으로** 계산(LLM 미사용).

### 2-1. 봇 판단 적중률 (forward return)
판단이 옳았는지를 **판단일 이후 실제 주가**로 채점한다.
```
ret_after(code, decision_date, N=5) = close[판단일+N거래일] / close[판단일 첫 종가] − 1
```
봇×판단별로 집계:
```
평균 수익률 = mean(rets)
상승률(win rate) = P(ret > 0)
적중 판정 = (매수 & 평균>0) 또는 (관망 & 평균≤0)  → "적중↑" / 아니면 "재점검 필요"
```
→ **매수는 올랐어야, 관망은 안 올랐어야 적중**. 관망의 기회비용까지 채점하는 게 핵심(안 사서 놓친 것도 실책으로 본다).

### 2-2. 오너 결재 부가가치 (approval alpha)
"사람이 결재 게이트에 서는 게 값을 하는가"를 잰다.
```
승인(매수)한 것들의 사후 수익률 = 최신가 / 판단가 − 1  (평균)
거부(패스)한 것들의 사후 수익률 = 최신가 / 판단가 − 1  (평균)
```
→ **승인분 평균 > 거부분 평균**이면 사람 판단이 봇을 개선한 것. **거부분이 더 올랐다면** 오너가 좋은 걸 막고 있다는 신호(자기 채점).

### 2-3. 관찰 단계 전환율
```
확신 전환 수 / (확신 + 철회)  → 신중함이 과한지(다 철회) or 무른지(다 확신) 진단
```

### 2-4. 데이터 헬스 요약
7일 성공/실패 집계 + 실패율 > 30%면 경고 → 판단 품질 저하 구간 식별.

## 3. 그 지표로 무엇을 개선하나 (improvement loop)

지표는 관상용이 아니라 **다음 행동의 트리거**다.

| 관측 지표 | 해석 | 개선 액션 |
|---|---|---|
| 특정 봇 **매수 적중률 낮음**(평균−, 상승률<50%) | 그 페르소나의 판단 잣대가 시장과 안 맞음 | 페르소나 프롬프트 튜닝 → `persona_hash`로 전후 버전 성과 비교(A/B) |
| **관망 판단이 계속 오름** | 봇이 너무 깐깐(기회 놓침) | 게이트 완화(예: 시드 재프레임 — 실제로 이 신호로 S 문턱 교정함) |
| **거부분 사후 수익 > 승인분** | 오너가 좋은 걸 반려 중 | 오너 결재 기준 재고 / 봇에게 더 위임 |
| **관찰 철회율 과다** | 딥스터디·관찰이 지나치게 보수적 | `OBSERVATION_MIN_REVIEWS`·딥스터디 강도 조정 |
| **관찰 확신율 과다** | 신중 장치가 무력 | 문턱 강화 |
| **데이터 실패율 급증** | 나쁜 데이터로 판단 중 | 세이프모드 자동 진입 / 시세 소스 이중화(로드맵) |
| **계좌 벤치마크 하회**(알파<0) | 전체 전략이 시장 못 이김 | 데스크별 분해로 원인 계좌 특정 → 사이징·유니버스 조정 |
| **한 트렌드 집중**(R 리스크 지적) | 단일 시나리오 몰빵 | 큐레이션 편중 상한(실제로 AI 최대 2개 규칙 도입) |

**루프의 형태**: `계측(자동) → 주간 채점(결정론) → 지표 해석 → 파라미터/프롬프트/게이트 조정 → 재계측`. 조정은 대부분 `.env 플래그·임계값` 또는 `persona_hash 추적 가능한 프롬프트`라 **되돌릴 수 있고 성과 대조가 가능**하다.

---

## 4. 현재 성숙도 & 한계 (정직판)
- ✅ **계측·재현성**은 완비(입력 패킷+페르소나 버전까지).
- ⚠️ **표본 부족**: 대부분의 봇 판단이 아직 7일 경과 전 → 채점 데이터가 쌓이는 중. 유의미한 결론엔 수십~수백 판단·수주가 필요.
- ⚠️ **forward return이 종가 기준**(체결 슬리피지·수수료 미반영) — 가상 단계 근사. 실매매 전 실체결가로 승격 필요.
- ⚠️ **리스크 조정 수익(Sharpe·MDD)** 은 아직 리포트에 없음 — 다음 계측 후보(fund_nav로 계산 가능).
- 실매매 전환 판단(P3)은 **90일 이상 누적 후** 벤치마크±리스크조정으로 결정.

> 요약: "봇이 무슨 판단을 했나(decision_log) → 그 판단이 옳았나(forward return) → 사람 게이트가 값을 했나(approval alpha) → 무엇을 조정할까"의 폐루프. 지금은 계측 인프라가 완성됐고, **데이터가 쌓이며 개선이 시작되는 단계**다.
